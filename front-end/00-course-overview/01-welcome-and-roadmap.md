# Module 00: Welcome, Learning Methodology & Roadmap

## 🎯 Course Goals & Learning Philosophy

Becoming a high-performing front-end engineer requires more than just memorizing syntax. It demands understanding:
1. **The Fundamentals**: How the browser interprets, parses, and paints your code.
2. **Mental Models**: How the Box Model calculates sizes, how the Flexbox formatting context calculates flex items, and how the JavaScript Call Stack and Event Loop interact.
3. **Engineering Discipline**: Version control, clean code architecture, accessibility (a11y), responsive design, and performance.

### The Problem with Modern Tutorials
Most modern frontend courses jump straight into heavy frameworks (React, Vue, Next.js) before learners understand:
- How HTML semantics affect screen readers and SEO.
- Why CSS specificity leads to `!important` wars.
- How JavaScript closures, prototypes, asynchronous event queues, and the DOM actually work under the hood.

This course takes the reverse approach: **You will master the foundational web platform first.** Once you understand HTML, CSS, and vanilla JavaScript deeply, any framework becomes intuitive to learn in a matter of days.

## 🧠 The "Active Coding" Rule
To get the most out of this course:
- **Never copy-paste code blindly.** Type it out. Muscle memory matters.
- **Inspect everything in Chrome DevTools:** Hit `F12` or `Ctrl+Shift+I` / `Cmd+Option+I` on every page you build. Use the Elements tab, Console tab, and Network tab constantly.
- **Break code on purpose:** What happens if you remove `box-sizing: border-box`? What happens if you forget `await`? What happens if you commit on a detached HEAD? Intentionally causing and fixing bugs is how senior developers learn.
